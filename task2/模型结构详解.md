# Task-2 三个模型结构详解

---

## 一、TextCNN（基于 Yoon Kim 2014 论文）

### 1.1 整体结构

```
输入: 句子 ID 序列 (batch_size=64, seq_len=80)
  ↓
Embedding 层: (64, 80) → (64, 80, 128)   # 每个词变成 128 维向量
  ↓
Dropout(0.5)
  ↓
Transpose: (64, 80, 128) → (64, 128, 80)  # Conv1d 要求 channel 在中间
  ↓
┌─────────────────────────────────────────────────────┐
│  三组并行卷积 (kernel_size 分别为 2, 3, 4)            │
│                                                      │
│  Conv1d(128→64, k=2): (64,128,80) → (64,64,79)      │
│  Conv1d(128→64, k=3): (64,128,80) → (64,64,78)      │
│  Conv1d(128→64, k=4): (64,128,80) → (64,64,77)      │
│                                                      │
│  每组接 ReLU + Max-over-time Pooling:               │
│  → 各输出 (64, 64)  # 从每个 channel 取最大值         │
└─────────────────────────────────────────────────────┘
  ↓
Concat: 拼接三路 → (64, 192)   # 64×3 = 192
  ↓
Dropout(0.5)
  ↓
Linear(192, 5): (64, 192) → (64, 5)   # 5 个类别
  ↓
输出: logits (64, 5)
```

### 1.2 关键设计说明

**为什么用多尺度卷积核？**

- `k=2`：捕获 bigram（相邻两个词的组合），如 "not good"、"very bad"
- `k=3`：捕获 trigram，如 "not very good"、"a great movie"
- `k=4`：捕获 4-gram，如 "one of the best"

每种大小的卷积核各自有 64 个 filter，总共 64×3=192 个特征。

**为什么用 Max-over-time Pooling？**

对每个 filter 的输出（长度 77~79）取最大值，而不是取平均。原因：
- 情感信号通常只出现在句子的某个局部（如 "absolutely terrible"）
- Max pooling 保留最强的信号，忽略无关内容
- 不管句子多长，pooling 后都变成固定长度

**参数量估算（baseline 配置）：**
- Embedding: 20000 × 128 = 2,560,000
- Conv1d × 3: 3 × (128 × 64 × k + 64) ≈ 3 × 10,000 = 30,000
- Linear: 192 × 5 + 5 = 965
- **总计约 2.59M 参数**（绝大部分在 embedding 层）

## 二、TextLSTM（双向 LSTM）

### 2.1 整体结构

```
输入: 句子 ID 序列 (batch_size=64, seq_len=80)
  ↓
Embedding 层: (64, 80) → (64, 80, 128)
  ↓
┌─────────────────────────────────────────────────────┐
│  BiLSTM (hidden_dim=128, bidirectional=True)         │
│                                                      │
│  前向 LSTM: 从左到右读句子                            │
│    h_0 → h_1 → h_2 → ... → h_79                     │
│                                                      │
│  后向 LSTM: 从右到左读句子                            │
│    h_79 ← h_78 ← h_77 ← ... ← h_0                   │
│                                                      │
│  输出: (64, 80, 256)  # 128×2 = 256 (双向拼接)        │
└─────────────────────────────────────────────────────┘
  ↓
提取句子表示:
  前向最后一个时间步: out[:, -1, :128]   # 读完整句话后的状态
  后向第一个时间步:   out[:, 0, 128:]    # 从末尾开始读的第一个状态
  拼接: (64, 256)
  ↓
Dropout(0.5)
  ↓
Linear(256, 5): (64, 256) → (64, 5)
  ↓
输出: logits (64, 5)
```

### 2.2 关键设计说明

**为什么用双向？**

- 前向 LSTM 只能看到"当前词及之前的词"
- 后向 LSTM 只能看到"当前词及之后的词"
- 双向拼接后，每个位置的信息都包含了完整的上下文
- 对于情感分类，"not good" 中 good 的语义需要 not 来反转，双向能同时利用两边的信息

**为什么取最后一个时间步而不是 mean pooling？**

- 最后一个时间步的 hidden state 理论上已经"读过了"整句话
- 但实际效果上 mean pooling 也常用，两者各有优劣
- 这里取最后一个时间步是更传统的做法

**参数量估算：**
- Embedding: 20000 × 128 = 2,560,000
- LSTM: 4 × [(128 + 128) × 128 + 128] × 2(双向) = 4 × 32,896 × 2 = 263,168
- Linear: 256 × 5 + 5 = 1,285
- **总计约 2.82M 参数**

## 三、TextTransformer

### 3.1 整体结构

```
输入: 句子 ID 序列 (batch_size=64, seq_len=80)
  ↓
Embedding 层: (64, 80) → (64, 80, 128)
  ↓
加位置编码: (64, 80, 128) + (1, 80, 128)  # 可学习的位置编码
  ↓
Dropout(0.1)
  ↓
┌─────────────────────────────────────────────────────┐
│  TransformerEncoder × 2 层                           │
│                                                      │
│  每层包含:                                           │
│  1. Multi-Head Self-Attention (4 heads)              │
│     - 每个 token 和其他所有 token 计算注意力权重       │
│     - 4 个 head 各自关注不同的关系                     │
│     - 输出: (64, 80, 128)                            │
│                                                      │
│  2. Feed-Forward Network                             │
│     - Linear(128→512) → ReLU → Linear(512→128)       │
│     - 对每个位置独立做非线性变换                       │
│                                                      │
│  3. 每个子层都有残差连接 + LayerNorm                   │
│     output = LayerNorm(x + Sublayer(x))              │
│                                                      │
│  4. Padding Mask: 忽略 <PAD> 位置的 token             │
│                                                      │
│  输出: (64, 80, 128)                                 │
└─────────────────────────────────────────────────────┘
  ↓
Mean Pooling（忽略 padding 位置）:
  对 80 个位置求平均（但跳过 <PAD>）→ (64, 128)
  ↓
Linear(128, 5): (64, 128) → (64, 5)
  ↓
输出: logits (64, 5)
```

### 3.2 关键设计说明

**Self-Attention 在做什么？**

对句子中的每个词，计算它和所有其他词的"关联程度"。例如：

```
句子: "the movie was not good at all"
处理 "good" 时，attention 会给 "not" 和 "at all" 高权重
→ 模型能理解 "not good at all" 整体是负面情感
```

4 个 head 各自关注不同的关系：
- Head 1: 可能关注否定词（not, never）和形容词的关系
- Head 2: 可能关注程度副词（very, extremely）和形容词的关系
- Head 3: 可能关注主语和谓语的关系
- Head 4: 可能关注其他语法关系

**为什么用 Mean Pooling 而不是 [CLS] token？**

- BERT 用 [CLS] token 的输出来做分类
- 这里没有 [CLS] token，所以用所有位置的平均（排除 padding）
- 简单有效，适合句子级分类任务

**位置编码为什么用可学习的而不是固定的？**

- 原始 Transformer 用 sin/cos 固定编码
- 这里用 `nn.Parameter(torch.randn(...))` 让模型自己学位置编码
- 在短句子任务上效果差不多，但代码更简单

**参数量估算：**
- Embedding: 20000 × 128 = 2,560,000
- Position Encoding: 80 × 128 = 10,240
- 每层 Attention: 4 × (128 × 128 × 3 + 128 × 128) = 262,144  (Q,K,V + Output)
- 每层 FFN: 128 × 512 + 512 + 512 × 128 + 128 = 131,584
- 每层 LayerNorm: 2 × (128 + 128) = 512
- 2 层总计: 2 × (262,144 + 131,584 + 512) = 788,480
- Linear: 128 × 5 + 5 = 645
- **总计约 3.36M 参数**

## 四、三个模型的对比

| 维度 | TextCNN | BiLSTM | Transformer |
|------|---------|--------|-------------|
| **核心机制** | 局部卷积 + Max Pooling | 序列递归 | 全局自注意力 |
| **感受野** | 受 kernel_size 限制（2~4 个词） | 全局（但远距离信息衰减） | 全局（所有位置平等） |
| **并行性** | ✅ 完全并行 | ❌ 必须按顺序 | ✅ 完全并行 |
| **位置信息** | 隐式（卷积核位置） | 隐式（序列顺序） | 显式（位置编码） |
| **参数量** | ~2.59M | ~2.82M | ~3.36M |
| **过拟合倾向** | 最低（参数少、结构简单） | 最高（递归结构容易记忆） | 中等 |
| **适合场景** | 短文本分类 | 需要理解长距离依赖 | 需要理解复杂语义关系 |
| **训练速度** | 最快 | 最慢 | 中等 |

### 实验结果印证

| 指标 | TextCNN | BiLSTM | Transformer |
|------|---------|--------|-------------|
| 10 epoch val_acc | 0.3910 | 0.4138 | 0.4209 |
| 过拟合程度 | 最轻 | 最重 | 中等 |
| val_loss 趋势 | 持续下降 | 先降后升 | 先降后升 |

- Transformer 上限最高（注意力机制最强），但需要更多数据和 epoch
- BiLSTM 在小数据集上过拟合最严重（train_loss 降到 0.62 但 val_loss 升到 1.70）
- TextCNN 最稳定但上限最低
